# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`ggpyramid` is an R package that extends ggplot2 for building population pyramids
(back-to-back bar charts of a population by age group and sex). It is Matan Hakim's
personal open-source package, public on GitHub at `matanhakim/ggpyramid`, with a
pkgdown site at https://matanhakim.github.io/ggpyramid/. Sibling packages by the same
author live next to it (`../il.cbs.muni`, `../rtlr`) and set the house conventions
for DESCRIPTION, pkgdown and CI; match them.

Status (Oct 2026): version 0.1.0, submitted to CRAN on 26.10.2026 and awaiting
review (`CRAN-SUBMISSION` records the commit). Exports: `geom_pyramid()`/`stat_pyramid()`,
`geom_pyramid_text()`, `geom_pyramid_outline()`, `position_pyramid()`,
`coord_pyramid()`, `scale_x_pyramid()`/`scale_y_pyramid()`, `theme_pyramid()`
and the `europe_pop` data (built by `data-raw/europe_pop.R` from Eurostat).
Design research, the architecture alternatives and the agreed API live in
`dev/design-research.md` (Hebrew); section 8 records Matan's decisions, and
nothing is implemented ahead of it. Throwaway prototypes are in `dev/spikes/`;
`dev/` is build-ignored.

Architecture: `PositionPyramid` (inherits `PositionStack`) owns correctness. It
negates the value axis for the `left` side, then stacks within each side, so
any geom can take `position = "pyramid"`. The side comes from the `side`
aesthetic (declared in the Position's `default_aes`), else `fill`, else
`colour`. The side drawn on the left is `position_pyramid(left)`, else
`coord_pyramid(left)` (read from `layout$coord` in `compute_layer()`), else the
first factor level. `StatPyramid` counts rows or sums a mapped value and writes counts
or, with `denominator`, proportions straight into the value axis; the
constructors attach a child stat whose `default_aes` only names the axis.
Orientation defaults to horizontal (age on y) when both axes are continuous.
`CoordPyramid` (inherits `CoordCartesian`, horizontal only) owns the look: it
wraps the x view scale for absolute labels, makes the limits symmetric, moves
the age scale in `modify_scales()`, and opens the centre gap in `transform()`,
which axis keys and grid lines also pass through. A zero belongs to the side
of its row; a lone zero on the left is a negative zero written by the
Position. Build negative zeros with `-abs(x)`: the byte compiler folds a
literal `-0` into `0`. Absolute labels go through `magnitude()` (rounded to 12
significant digits) so float noise cannot label the two sides differently.
`GeomPyramidText` and `GeomPyramidOutline` prepare the data and delegate the
drawing to `GeomText` and `GeomPath`.

## Commands

R is not on PATH in the Bash tool. Use the full path:

```bash
RS="/c/Program Files/R/R-4.5.2/bin/Rscript.exe"
"$RS" -e 'devtools::document()'          # regenerate man/ and NAMESPACE from roxygen
"$RS" -e 'devtools::test()'              # all tests
"$RS" -e 'devtools::test(filter = "coord")'   # one file: tests/testthat/test-coord-pyramid.R
"$RS" -e 'devtools::check()'             # full R CMD check
# as CRAN: check(remote = TRUE, env_vars = c(NOT_CRAN = "false")); no LaTeX here
"$RS" -e 'devtools::build_readme()'      # re-knit README.Rmd -> README.md
"$RS" -e 'pkgdown::build_site()'         # local site into docs/ (gitignored)
"$RS" -e 'lintr::lint_package()'
air format R tests                       # format package code (not dev/ spikes)
```

Plot tests use `vdiffr` snapshots in `tests/testthat/_snaps/`; review changed
ones with `testthat::snapshot_review()`. Multi-line `Rscript -e` calls print
nothing in the Bash tool; write the code to a file in the scratchpad and run that.

## Conventions

- Edit `README.Rmd`, never `README.md`; re-knit after changes and commit both.
- NAMESPACE and `man/` are generated by roxygen2 (markdown enabled); never hand-edit.
- Call ggplot2 functions with `ggplot2::` or add `@importFrom` in the roxygen block.
  `R/ggpyramid-package.R` holds package-level imports.
- testthat edition 3. New code goes in `R/<topic>.R` with `tests/testthat/test-<topic>.R`.
- Add every user-visible change to `NEWS.md`. While the only entry is
  "(development version)", R CMD check reports a "No news entries found" NOTE; it is
  expected and disappears at the first numbered release.
- `.gitattributes` forces LF line endings; CI runs on Linux, macOS and Windows.

## CI and publishing

- `.github/workflows/R-CMD-check.yaml` (r-lib check-standard) runs on push/PR to main.
- `.github/workflows/pkgdown.yaml` builds the site and deploys to the `gh-pages`
  branch, which GitHub Pages serves. Reference index layout goes in `_pkgdown.yml`.
  `development: mode: auto` publishes a release version at the root and a
  `.9000` version under `/dev/`.
- pkgdown renders every top-level `.md` (except README, NEWS, LICENSE and
  cran-comments) into the site, which is why this file lives in `.claude/`. Keep
  internal notes out of the root. The deploy uses `clean: false`, so a page
  published by mistake stays on `gh-pages` until it is deleted from that branch.
- The repo is public: everything committed is published.
